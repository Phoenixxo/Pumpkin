# Bottlenecks, mitigations, and proof points

[Documentation index](../README.md) · [Overview](overview.md) · [Spatial ownership and ECS](spatial-ownership-and-ecs.md) · [Networking](networking.md) · [Plugin pipeline](plugin-pipeline.md)

Changing the concurrency model moves pressure rather than making it disappear. Region ownership reduces shared writes, but introduces mailboxes, state handoffs, snapshots, and cross-owner messages. Shared packet frames reduce repeated encoding, but increase retained memory and still require connection-specific encryption. The matrix records these tradeoffs alongside the evidence needed to decide whether each design helps. [Phase 00](../phases/00-baseline-and-benchmarks.md) establishes a baseline, and [phase 05](../phases/05-capacity-validation.md) evaluates the whole system under load. End-to-end p99 latency and correctness matter more than an isolated microbenchmark.

| Pressure point | Cause or risk | Mitigation | Evidence to collect |
| --- | --- | --- | --- |
| Joined tick | The slowest world or phase delays the current ticker. | Schedule independent regions separately and publish global updates with timestamps. | Measure tick p50/p95/p99, lateness by region, and progress in unaffected regions during a hotspot. |
| Single hot owner | Dense collision, combat, redstone, and plugin decisions can require serial execution. | Keep the strict interaction island as small as semantics allow; run AI plans, entity batches, encoding, and lighting outside it. | Measure mandatory serial CPU time, cross-owner messages, and the age of the region backlog. |
| Dynamic split/merge | Frequent repartitioning transfers state and invalidates routing. | Apply a cost model with hysteresis, then hand off ownership at a tick boundary using a new generation. | Record migrations per minute, transferred bytes, stale command rejections, and replay equivalence. |
| Cross-owner commands | Small cells increase message volume and may create dependency cycles. | Merge strongly coupled cells and give remaining messages causal IDs, deadlines, and deterministic commit order. | Count messages per interaction and inspect the wait graph, missed deadlines, and consistency assertions. |
| Global or chunk locks | A lock held during player scans, generation, or an await can stall unrelated work. | Restrict locks to brief control-plane changes; keep mutations with actors and publish immutable halos for readers. | Measure lock wait and hold times alongside the number of blocked cores. |
| Snapshot publication | Copying whole worlds would consume memory bandwidth and retain large generations. | Publish changed sections or chunks and small border halos, reusing immutable `Arc` values where possible. | Track snapshot bytes per tick, retained generations, and the stale-result rate. |
| Cache misses and false sharing | Trait objects, per-field atomics, and interleaved entity state scatter the hot working set. | Store hot fields in owner-local structure-of-arrays batches, separate cold components, and size batches from profiles. | Compare last-level cache misses, cycles per entity tick, and cache-line contention. |
| ECS structural churn | Spawn, despawn, and component changes can move rows while systems iterate. | Defer structural changes until owner commit and group compatible changes by archetype. | Track rows moved per tick, allocations, and spawn/despawn p99 latency. |
| Tiny Rayon jobs | Queueing and stealing can cost more than the work inside a small job. | Offload only audited plugin-free CPU batches above a measured threshold; run small steps on the managed owner task and give background jobs a separate admission budget. | Measure scheduling cost per job, worker utilization, and the useful CPU fraction on small as well as crowded servers. |
| Generation and lighting | Chunk generation and inline light propagation can consume the active tick budget. | Preserve a bounded generation pool, version lighting results, and reserve CPU for simulation. | Compare background queue age and active-region p99 while checking lighting correctness at publication. |
| Observer discovery | A world-wide scan grows with every player, even when only nearby viewers matter. | Index observers by section and apply the exact visibility filter after lookup. | Compare index candidates with actual recipients and measure lookup CPU. |
| All-to-all broadcast | A dense crowd produces quadratic recipient deliveries. | Enforce per-client and global byte budgets, coalesce replaceable updates, and define an interest and cadence policy. | Record deliveries and bytes per second, visible-state age, and required-packet latency. |
| Repeated compression | The same Java payload can be compressed separately for many connections. | Cache compressed frames by protocol version, compression profile, and content revision. | Measure compression cycles, cache hit rate, and the number of frames built. |
| Per-client cipher | Java CFB8 and transport encryption carry connection-specific state. | Keep one writer per connection, batch writes, and reserve sufficient crypto CPU. | Measure cycles per byte, socket backpressure, and writer queue age. |
| Queue retention | Per-client limits still allow aggregate queued memory to grow with player count. | Acquire weighted global and per-client byte permits before retaining frames and apply a defined slow-client policy. | Track retained frame bytes, resident memory, queue age, and evictions. |
| WASM guest CPU | An asynchronous host import does not preempt a guest that never imports or yields. | Enforce fuel or epoch interruption and memory and host-call quotas. A caller deadline stops waiting for a result; it does not itself terminate accepted guest work. | Measure guest CPU per invocation, traps, missed deadlines, and reactor latency. |
| Plugin decision ordering | A blocking event needs its returned event before world commit; nonblocking callbacks' returned events are ignored. | Suspend the managed transaction, release world and Store borrows, then validate the owner generation and transaction revision before applying a blocking reply. | Measure origin wait time, late replies, stale-result rejection, and cancellation parity. |
| Permanent v0.1 admission lane | A fair graph-wide gate preserves v0.1 synchronous reentry, but occupies its compatibility worker while a legacy call waits. | Keep the lane for v0.1 and put eligible v0.2 components on the separate concurrent policy. Carry the same legacy admission token across domain hops. | Measure gate occupancy, queue age, legacy worker time, and mixed-ABI event throughput. |
| Managed task and domain queues | Plugin-capable roots need scheduler admission before suspension. Extra routing can outweigh any parallelism benefit on a small server, and cross-domain host calls can queue behind a busy owner. | Start with Global domain, use bounded queues and inline same-domain operations when safe, and add Region or Entity domains only after measurements and ordering tests justify them. | Compare task-poll cost, queue age, host-call latency, and p99 tick on small and dense workloads in Global and regional modes. |
| Accidental plugin entry from Rayon | A CPU leaf may reach a callback or host import through an indirect code path, trapping a worker and bypassing admission. | Audit leaf call graphs and fail closed at runtime: reject and resubmit plugin-capable work as a managed task, with no Store or owner borrow carried across the boundary. | Count rejected leaf entries and verify worker progress under nested plugin and host-call stress. |

The upstream [ticker](../../crates/pumpkin/src/server/ticker.rs), [world state](../../crates/pumpkin/src/world/mod.rs), [Java outgoing writer](../../crates/pumpkin/src/net/java/outgoing.rs), [plugin dispatch](../../crates/pumpkin/src/plugin/mod.rs), and [Global scheduler scaffold](../../crates/pumpkin-scheduler/src/global.rs) provide concrete places to begin instrumenting. The mitigations remain proposals until the measured workload establishes both a performance benefit and acceptable behavior under overload.
